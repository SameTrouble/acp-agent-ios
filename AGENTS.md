## Repo overview

Monorepo with two deployable artifacts:

- **`companion/`** — Bun + TypeScript WebSocket server that bridges ACP
  (Agent Client Protocol) agents to iOS clients over JSON-RPC. Spawns
  `opencode acp` as a subprocess.
- **`ios/`** — Swift 6 iOS app + Swift Package (`ACPAgentKit`). iOS 17+
  minimum. App is generated by **xcodegen** from `ios/App/project.yml`.

Domain glossary lives in `CONTEXT.md` — use its exact terms (Session,
Conversation, Transcript, ConversationStore, etc.) and avoid the
synonyms it explicitly rejects. Architectural decisions in `docs/adr/`.

## iOS (`ios/`)

### Architecture

- `ACPAgentKit` is a Swift Package (`ios/ACPAgentKit/Package.swift`).
  It exports one library: **`ACPAgentCore`**.
- `Sources/ACPAgentCore/` — wire protocol, state models, `ACPClient`,
  `ConversationStore`. Fully testable without a UI host.
- `Sources/ACPAgentUI/` — **empty**, reserved for future reusable UI
  components. SwiftUI views live in the app target, not here (ADR-001).
- `ios/App/` — the app target. Views are thin SwiftUI layers that read
  `ACPClient` as `@EnvironmentObject` and call its public methods.
  Views never reach into `JsonRpcClient` or `WebSocketTransport`
  directly (ADR-001).
- **`ACPClient` is the sole view-facing seam.** `ConversationStore`
  owns per-session conversation state; `ACPClient` delegates to it but
  remains the only `ObservableObject` views see (ADR-004).

### Build & run

The Xcode project is **generated**, not hand-edited. Regenerate after
adding files or changing `project.yml`:

```sh
cd ios/App && xcodegen generate
```

Open `ios/App/ACPAgent.xcodeproj` in Xcode to build/run. Bundle ID:
`com.acp-agent.ios`. Automatic code signing — set
`ACP_DEVELOPMENT_TEAM` env var to your 10-char team ID.

### Tests

Run from the Swift Package:

```sh
cd ios/ACPAgentKit && swift test
```

Run a single test: `swift test --filter ACPAgentCoreTests.ConversationStoreTests`

### Release (TestFlight)

```sh
ios/scripts/release-testflight.sh
```

Requires: xcodegen, App Store Connect API key in
`~/.appstoreconnect/private_keys/`, env vars `ACP_ASC_KEY_ID` and
`ACP_ASC_ISSUER_ID`. Build number defaults to `git rev-list --count HEAD`.
Use `--no-upload` for a local IPA only. Full guide: `ios/RELEASE.md`.

### Notable quirks

- ATS: `NSAllowsArbitraryLoads` is enabled — the app connects to the
  user's own companion server at arbitrary addresses (LAN IPs, VPN IPs,
  self-hosted domains).
- `ACPAgentUI` source folder exists but is intentionally empty. Don't
  put views there without a new ADR.

## Companion (`companion/`)

### Setup & run

```sh
cd companion
bun install
bun run start /path/to/companion.json
```

Config format: see the root `README.md` §companion 配置 or
`companion/config.example.json`. Default config path:
`~/.config/acp-agent/companion.json`.

### Verify

```sh
cd companion
bun run typecheck   # tsc --noEmit
bun test            # full suite, spins up server against mock agent
```

Run a single test file: `bun test test/server.test.ts`

### Key modules

- `src/server.ts` (661 lines) — WebSocket JSON-RPC server, session
  lifecycle, broadcast. Main orchestrator.
- `src/acp.ts` — ACP subprocess spawn + handshake.
- `src/session.ts` — per-session state machine on the server side.
- `src/prompt-expander.ts` — expands `file_ref` blocks to `resource`
  or `resource_link` based on agent capability.
- `src/bark.ts` — Bark push notifications for approvals and session ends.

Test helpers: `test/helpers/mock-agent.ts` (base mock),
`mock-agent-approval.ts`, `mock-agent-no-embedded.ts`,
`mock-agent-no-load.ts`.

### Deploy

```sh
cd companion
bun run build:linux   # cross-compiles to dist/acp-companion-linux-x64
```

Single binary, no node/bun needed on the server. Systemd unit in
`companion/deploy/acp-companion.service`. Full guide:
`companion/DEPLOY.md`.

## Workflow conventions

- **`main` is only ever modified through a pull request.** Never commit
  or push directly to `main`. Always branch (e.g. `feat/<topic>`,
  `fix/<topic>`), push the branch, and open a PR with `gh pr create`.
- Commit messages reference the issue number (e.g. `(closes #14)`).
- Release builds are cut from `main` after the PR merges.
- ADRs are numbered `0001-*` and live in `docs/adr/`. If your work
  contradicts an existing ADR, flag it explicitly.
